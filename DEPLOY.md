# Выкладка «Пути джуна» на game.workaem.com

Полный путь от локальной сборки до работающего Mini App в Telegram.
Занимает около получаса, из них половина — ожидание DNS.

---

## Что понадобится

- [ ] Доступ по SSH к серверу, где крутится workaem
- [ ] Доступ к DNS-панели домена workaem.com
- [ ] Права на правку Caddyfile и перезапуск Caddy
- [ ] Telegram под рукой (нужен @BotFather)
- [ ] Картинка 640×360 для витрины Mini App

---

## Шаг 1. Собрать локально

```bash
npm install
npm run build
```

Сборка не пройдёт, если хоть одна карта окажется непроходимой —
это встроенная проверка, а не косметика. В `dist/` должно получиться около 30 КБ:

```bash
du -sh dist && ls -la dist/assets
```

Прогони локально перед выкладкой:

```bash
npm run preview   # http://localhost:4173
```

---

## Шаг 2. DNS

В панели домена `workaem.com` добавить запись:

| Тип | Имя | Значение | TTL |
|-----|-----|----------|-----|
| A | `game` | IP сервера с workaem | 300 |

Если сервер за Cloudflare — тип тот же, прокси **выключить** (серое облако)
на время выпуска сертификата, иначе Caddy не пройдёт проверку.

Дождаться распространения:

```bash
dig +short game.workaem.com
```

Должен вернуться IP сервера. Обычно 1–15 минут.

---

## Шаг 3. Caddy

Caddy сам выпускает и продлевает сертификат Let's Encrypt — именно поэтому
он здесь удобен: Telegram без валидного HTTPS Mini App не примет.

Добавить в Caddyfile:

```caddy
game.workaem.com {
    root * /var/www/junior-way
    file_server
    encode gzip zstd

    # Ассеты собираются с хешем в имени — их можно кешировать навсегда
    @assets path /assets/*
    header @assets Cache-Control "public, max-age=31536000, immutable"

    # index.html не кешируем, иначе игроки застрянут на старой версии
    @html path /
    header @html Cache-Control "no-cache"

    # Telegram открывает Mini App во встроенном webview
    header X-Content-Type-Options "nosniff"
    header Referrer-Policy "strict-origin-when-cross-origin"
}
```

Создать каталог и применить:

```bash
sudo mkdir -p /var/www/junior-way
sudo chown -R $USER:$USER /var/www/junior-way

sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

---

## Шаг 4. Выложить

С локальной машины:

```bash
DEPLOY_HOST=user@server DEPLOY_PATH=/var/www/junior-way npm run deploy
```

Или вручную:

```bash
rsync -az --delete dist/ user@server:/var/www/junior-way/
```

---

## Шаг 5. Проверить, что живо

```bash
curl -sS -o /dev/null -D - https://game.workaem.com/ | head -5
```

Нужен `HTTP/2 200`. Если `525` или ошибка сертификата — Caddy ещё не выпустил
сертификат, посмотри `sudo journalctl -u caddy -n 50`.

Открой `https://game.workaem.com` в обычном браузере: игра должна работать
на стрелках и пробеле. Telegram-функции (вибрация, имя игрока) там не работают —
это нормально, они появятся только внутри Telegram.

## Шаг 6. Бот и Mini App

Всё в чате с [@BotFather](https://t.me/botfather).

### Если бота ещё нет

```
/newbot
```
Имя → юзернейм (должен кончаться на `bot`, например `workaem_bot`).
BotFather выдаст **токен** — он нужен для будущей таблицы рекордов.
⚠️ Токен в репозиторий не класть никогда, только в переменные окружения.

### Создать Mini App

```
/newapp
```

BotFather спросит по порядку:

1. **Бот** — выбрать из списка
2. **Название** — `Путь джуна`
3. **Описание** — `Аркада про карьеру в IT. Растопчи легаси, дойди до оффера.`
4. **Картинка 640×360** — витрина приложения
5. **URL** — `https://game.workaem.com`
6. **Короткое имя** — `game` (попадёт в прямую ссылку)

После этого игра открывается по прямой ссылке:

```
https://t.me/workaem_bot/game
```

Именно её и кидаешь в канал.

### Кнопка в меню бота

Чтобы игра запускалась и из самого бота:

```
/setmenubutton
```
Выбрать бота → URL `https://game.workaem.com` → текст кнопки `Играть`.

### Deep links для аналитики

К прямой ссылке можно добавлять параметр — он придёт в `initData`:

```
https://t.me/workaem_bot/game?startapp=kanal
https://t.me/workaem_bot/game?startapp=habr
```

Так видно, откуда пришёл игрок, без внешней аналитики.

## Шаг 7. Проверить в Telegram

Открыть ссылку **с телефона**, не с десктопа — играть будут пальцем.

- [ ] Игра открывается на весь экран
- [ ] Кнопки ◀ ▶ ▲ нажимаются пальцем без задержки
- [ ] Вибрация на растаптывании врага и на коммите
- [ ] На финальном экране видно имя из Telegram
- [ ] Кнопка «Вакансии на твой грейд» открывает workaem
- [ ] Кнопка «Поделиться» предлагает выбрать чат

Если имя игрока не появилось — `initData` не пришёл. Проверь, что открывал
именно по ссылке `t.me/...`, а не по прямому адресу сайта.

---

## Шаг 8. Обновления

Дальше каждая выкладка — одна команда:

```bash
npm run deploy
```

Игроки получат новую версию при следующем открытии: `index.html` не кешируется,
а ассеты приходят с новыми именами.

## Чего пока нет

**Таблицы рекордов.** Для неё нужен серверный кусок, которого мы ещё не писали:

1. Эндпоинт, принимающий результат забега
2. Проверка `initData` — HMAC-SHA-256 строки данных ключом, который сам
   является HMAC-SHA-256 от токена бота с константой `WebAppData`,
   сравнение constant-time, проверка срока `auth_date`
3. Отсечка накрутки по `RunStats`: кадры, прыжки, растаптывания, смерти —
   уровень за восемь секунд физически невозможен
4. Хранилище с недельным сбросом и разбивкой по специализациям

Без этого игра полностью работает — нет только соревнования.

## Если что-то сломалось

| Симптом | Причина | Что делать |
|---|---|---|
| Сертификат не выпускается | Cloudflare-прокси включён | Выключить оранжевое облако, подождать |
| `404` на всё | Неверный `root` в Caddyfile | Проверить путь и права на каталог |
| Белый экран в Telegram | Ошибка JS | Открыть тот же URL в браузере, посмотреть консоль |
| Игра старая после выкладки | Кеш `index.html` | Проверить заголовок `Cache-Control: no-cache` |
| Нет имени игрока | Открыто не через Telegram | Заходить по ссылке `t.me/бот/game` |
| Кнопки не нажимаются | Не тот `touch-action` | Проверить, что в CSS у `.pad button` стоит `touch-action: none` |
